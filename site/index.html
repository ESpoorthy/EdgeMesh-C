Request lifecycle

From incoming request to healthy backend.

A compact networking pipeline with bounded request handling and explicit failure paths.

01 / INGRESS

Accept & validate

The proxy accepts a client connection and parses the supported HTTP/1.1 GET request subset.

02 / SELECT

Choose a route

Round Robin or Least Connections selects an eligible backend from the configured pool.

03 / FORWARD

Forward & observe

The proxy forwards the request and records request outcomes, timing and traffic metrics.

04 / RECOVER

Detect & fail over

Health checks track backend availability so unhealthy nodes can be excluded from routing.

Core capabilities

Built around visibility and resilience.

⇄

Load balancing

Compare Round Robin and Least Connections request-selection strategies across a backend pool.

♡

Backend health

Track backend health state and prevent unhealthy nodes from receiving new traffic.

↗

Automatic failover

Attempt eligible alternate backends when an upstream failure occurs within the supported retry rules.

◷

Traffic metrics

Collect request rates, response outcomes, latency observations and backend-level activity.

⌘

Admin API

Expose health, overview, backends, routing policy, metrics and latest benchmark information.

Build & run instructions ↗
# Build the C engine
cmake -S . -B build
cmake --build build --parallel

# Start three demo backends
./build/demo_backend 9001 &
./build/demo_backend 9002 &
./build/demo_backend 9003 &

# Start proxy + admin API
./build/edgemesh
